# 第 1 輪 PDCA：匯入、匯出、保存與還原

## 已重現的問題

- GitHub 分支的模組入口無法解析：`src/app.js` 缺少第一個 `import {`，而 `src/importer.js` 缺少資料模型匯入。
- `npm test` 的測試檔未匯入 `node:test`，因此在第一個測試就停止。
- 舊整合版 `ChronoDesk-整合版.html` 將 `chartInstances` 宣告為 `const` 後又在 `drawCharts()` 重新賦值；ECharts 成功載入時會拋出錯誤。此檔案已降為相容性材料，不是正式入口。
- 原本匯入預覽沒有列出無效欄位、日期範圍或分類統計；ICS 匯出少了秒數，且未宣告台北時區。

## 已完成的修正

- 模組版與單檔版共用 `src/` 的資料模型、排程、分析、匯入和介面來源；`npm test` 會先重建 `ChronoPlanner-可直接開啟.html`。
- 一般匯入預設合併新增，重複活動可逐筆選擇新增、略過或更新。
- 匯入前顯示檔名、格式、日期範圍、分類筆數、有效／重複／異常筆數與各筆異常欄位；無效資料不會被正規化成假日期或假時段。
- JSON 會保留任務、行程、實際紀錄、回顧與目標的 ID 關聯；重新開啟後會從本機儲存還原。
- ICS 以 `Asia/Taipei` 匯出；UTC 時間轉為台北時間。尚未支援的 RRULE 或非台北 TZID 會在預覽中列出並略過，不會靜默改寫。
- 新增合成 JSON 與 ICS 測試資料；根目錄改為指向離線單檔的正式入口頁。

## 驗收結果

- `npm test`：15 項核心測試通過。
- Chromium：模組版與單檔版均能載入，沒有 page error。
- Chromium：JSON 匯入後顯示 4 筆行程與其關聯資料，重新載入後仍存在。
- Chromium：ICS 預覽顯示 2 筆有效行程與 1 筆未支援 RRULE；匯出的 ICS 包含 `Asia/Taipei`、秒數與跨午夜結束日期。

## 限制與下一步

- 瀏覽器測試環境禁止直接以 `file://` 導覽，因此以 HTTP 載入同一份單檔驗證腳本與互動；單檔本身不含外部資源。
- ICS 尚未支援 RRULE、非台北 TZID 的時區轉換與完整 VTIMEZONE 定義；它們會被明確拒絕而非轉成錯誤時間。
- 下一輪處理行事曆與工作台：新增／編輯／刪除／復原、未排程任務、跨午夜與重疊的操作驗收。
